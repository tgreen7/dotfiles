1. Order intake starts in eComm/Ohm and is tracked in MES/Artik.
2. Artik sends characterization work to Maestro.
3. Maestro directs operator setup for NanoTemper run (nDSF and/or DLS).
4. Operator confirms instrument setup in Maestro.
5. Instrument run executes.
6. Instrument outputs land in S3 instrument storage (and related run artifacts).
7. Maestro provides run metadata/location into Caliber for AB_NDSF and AB_DLS paths.
8. Automated branch: pipeline/automation signals Caliber that processed run outputs are ready (Caliber automatic intake endpoint supports AB_NDSF and AB_DLS).
9. Caliber automatic NanoDSF/DLS manager reads ndsf or dls subfolder from S3 path, parses xlsx, associates sample details, stores QC results.
10. Caliber exposes these results for review gates.
11. Koala supervisor review runs in the NanoDSF+DLS review experience (combined view with NanoDSF and optional DLS section).
12. Supervisor approves/overrides QC decisions.
13. Koala review outcome is persisted back through Caliber QC review flow.
14. ADS receives characterization rows through manufacturing_systems lineage (via lab-data-loader synchronization) and serves ndsf/dls through registry factories.
15. ADS characterization endpoint aggregates by order and assay for downstream consumers.
16. eComm/Ohm downstream closeout flow proceeds once order-level release conditions are satisfied (through existing Artik/Caliber release chain).
17. Manual and fallback variants captured in code and your notes

18. Direct ADS API upload branch: caller posts to ADS analysis upload endpoint with assay_type ndsf or dls, s3_path, file_name, item_map.
19. ADS NanoTemper service parses data, stores rows, copies SVG images, and returns accepted processing status.
20. Tahoe manual branch: user uploads traditional DLS/nanoDSF files (collateral + rawdata) for Tahoe-local processing.
21. Tahoe hybrid branch: user provides order items to Tahoe upload endpoints; Tahoe pulls ndsf/dls from ADS characterization API and merges into Tahoe master data.
22. Tahoe then includes these in generated collateral/master outputs for manual workflows.
23. Mixed-order behavior: automated assays can come from ADS while other assays are still Tahoe-local and stitched together at collateral generation time.



Current Setup: Testing uses 384-well plates starting at the "stamp" step and moving into "initiation."

# Nano DSF + DLS Unified Workflow

1. Order intake starts in eCommerce/Ohm and is tracked in MES/Artik by order item.
2. Artik sends characterization work to Maestro, preserving order item to sample mapping.
3. Maestro generates the NanoTemper worklist for DSF and optional DLS on the 384-well plate workflow.
4. Operator stages plate and samples (current operational staging includes UA-2B handling) and runs instrument setup.
5. Sequence information is used in MES for concentration calculations, but sequence information is not required to load or run the instrument.
6. NanoTemper run executes; data is written to the instrument production folder.
7. Instrument integration mirrors run outputs from local production storage to S3 as the system of record.
8. S3-first ingestion is the primary strategy; Maestro is not the primary file-upload path.
9. DSF and DLS outputs are handled as separate assay artifacts and must remain separable through intake and storage.
10. Run metadata and S3 locations are registered for downstream processing and plate completion tracking.
11. Automated analysis workers (Airflow/automation pipeline) detect new S3 artifacts and trigger assay processing.
12. Caliber intake reads assay-specific files from S3, parses raw values, maps them to order items/samples, and stores post-analyzed QC-type values.
13. If local/manual analysis is required (including larger order workflows), exported files are still stored in S3 and can be consumed by downstream services.
14. Koala presents review gates as DSF view, DLS view, and an aggregated QC view over the same order context.
15. Reviewer verifies that expected data is present and coherent; current Nano DSF QC does not enforce strict universal pass/fail thresholds.
16. Caliber persists gate outcomes and exposes approved characterization values for release and reporting flows.
17. Manufacturing lineage synchronization publishes characterization rows so ADS can aggregate by order and assay.
18. For mixed-assay orders, ADS serves supported assays and interoperates with Tahoe APIs for unsupported assay types.
19. Customer-facing collateral is emitted in one aligned output format by Tahoe v1.1, Tahoe v2 (ADS), or the aggregation service; MES collateral format is not changed in this phase.
20. Automation roadmap extends processing with generated plots (including melting-curve visualizations) for verification and eventual customer-facing inclusion.
21. Operational release sequencing remains phased: Nano DSF automation target by March 15, with broader ADS/aSEC mixed-assay integration in the April release window.
22. Final QC trigger semantics, mixed-order routing edge cases, and S3 file naming/sync ownership remain tracked decisions that must be finalized before full production hardening.
